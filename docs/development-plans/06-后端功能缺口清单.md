## 一、当前结论

## 三、契约兼容说明

- LLM Provider 管理：ADMIN 使用 `/api/v1/admin/llm-providers`（CRUD/启停/测试）；OWNER 使用 `GET /api/v1/llm-providers`（只读启用模型列表）。Admin 统一管理加密 API Key，Owner 只选择模型。
- Review 批量接口同时保留现有 `/batch/approve|reject|mark-manual|assign` 路径，并补充契约兼容路径 `/batch-approve`、`/batch-reject`、`/batch-mark-manual`、`/batch-assign`。
- Submission 状态契约不再包含 `AI_REJECTED`；历史数据通过迁移转换为 `PENDING_FINAL`。
- Review 动作使用 `AI_DIRECT_REJECT` 表示 AI 直接打回，避免与人工 `REJECT` 混淆。

## 四、验收方式

- `ApiContractMappingTest` 覆盖契约中 P0/P1 入口映射。
- 全量回归以 `mvn test` 为准。
