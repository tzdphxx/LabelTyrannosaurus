# 09-管理端数据看板需求文档

> 面向 FE、BE-A、BE-B 与 AI 开发工具：本文档定义 LabelHub 角色数据看板体系中的 `ADMIN` 管理端数据看板首版需求。本文只详细展开管理端数据看板，不覆盖 Owner、Labeler、Reviewer 的角色看板细节；其他角色后续可按本文的路由、权限、指标口径方式扩展。

## 0. 文档目标

当前平台已经具备 Owner 任务管理、Labeler 标注、Reviewer 审核、奖励贡献统计、审计等业务能力，但管理员侧主要集中在用户管理，缺少一个可以快速理解平台运行状态的管理端首页。

本需求目标是新增管理端数据看板，让管理员登录后可以在一个页面内看到全平台运营状态，并快速进入用户管理等后台能力。

首版定位：

- 管理端首页，不是普通业务角色工作台。
- 数据看板优先，不在首页直接执行高风险管理操作。
- 用户管理作为管理端首个配套模块，复用现有 Admin 用户管理接口。
- 默认展示近 7 天数据，支持切换近 30 天。
- 奖励相关只展示摘要，不展开奖励流水明细。

## 1. 范围边界

### 1.1 P0 范围

P0 必须交付：

- `ADMIN` 专属前端入口和导航。
- 管理端数据看板首页。
- 平台运营 KPI 概览。
- 用户、任务、提交、审核、奖励摘要、异常提醒。
- 用户管理入口。
- 管理端看板聚合接口草案。

### 1.2 P0 不做

P0 不做以下能力：

- 不在看板首页直接启用、禁用用户或修改角色。
- 不在看板首页直接暂停、结束、删除任务。
- 不展示完整奖励流水、冲正明细或财务对账。
- 不实现 Owner、Labeler、Reviewer 看板详情需求。
- 不新增复杂自定义日期范围，首版只支持近 7 天和近 30 天。

## 2. 用户与权限

### 2.1 目标用户

目标用户为平台管理员 `ADMIN`。

管理员需要回答的问题：

- 平台现在是否正常运转？
- 最近一段时间任务、提交、审核是否增长或积压？
- 是否有异常任务、异常账号或待关注风险？
- 奖励支出是否在合理范围内？
- 是否需要进入用户管理处理账号或角色问题？

### 2.2 权限规则

- 仅 `ADMIN` 可访问管理端数据看板。
- 未登录访问时跳转登录页或返回 `401001`。
- 非 `ADMIN` 访问时前端不展示入口；后端接口返回 `403001`。
- 用户管理操作继续遵循现有 `/api/v1/admin/users` 权限规则。

## 3. 页面需求

### 3.1 路由与导航

建议新增前端路由：

```text
/app/admin
/app/admin/users
```

建议新增管理端导航：

| 导航 | 路径 | 说明 |
| --- | --- | --- |
| 数据看板 | `/app/admin` | 管理端首页，展示平台运营摘要 |
| 用户管理 | `/app/admin/users` | 用户列表、角色、启禁用、审核员创建 |

后续角色看板可保持同类结构：

```text
/app/owner
/app/labeler
/app/reviewer
```

OWNER、LABELER、REVIEWER 看板只消费自己权限范围内的数据，不能互相读取；ADMIN 作为最高权限角色，可跨角色访问业务数据。

### 3.2 首页线框

```text
+--------------------------------------------------------------------------------+
| 管理端数据看板                                      [近7天 v] [刷新]           |
+--------------------------------------------------------------------------------+
| 活跃任务 | 已领取数 | 已提交数 | 待审核数 | 通过率 | 打回率 | 奖励支出          |
+--------------------------------------------------------------------------------+
| 提交/审核趋势折线图                         | 任务状态分布 / 角色分布         |
| - submitted_count                           | - DRAFT/PUBLISHED/PAUSED/ENDED |
| - approved_count                            | - ADMIN/OWNER/LABELER/REVIEWER |
| - rejected_count                            |                                 |
+--------------------------------------------------------------------------------+
| 异常提醒                                      | 标注员贡献排行 / 任务产出排行   |
| - 审核积压任务                                | - labeler submitted/approved    |
| - 打回率偏高任务                              | - task submitted/approved       |
| - 禁用账号/异常账号                            | - reward amount summary         |
+--------------------------------------------------------------------------------+
| 用户管理入口：用户总数 / 各角色人数 / 禁用账号数 / 最近新增用户     [进入管理] |
+--------------------------------------------------------------------------------+
```

### 3.3 交互规则

- 时间范围切换：
  - 默认 `近 7 天`。
  - 可切换 `近 30 天`。
  - 切换后所有 KPI、趋势、排行、异常提醒同步刷新。

- 刷新：
  - 点击刷新按钮重新请求看板聚合接口。
  - 加载中展示骨架屏或卡片 loading。

- 用户管理入口：
  - 点击进入 `/app/admin/users`。
  - 不在首页直接修改用户状态或角色。

- 空状态：
  - 无任务、无提交、无奖励时显示 `0` 和空趋势。
  - 异常提醒为空时显示“暂无需要处理的异常”。

## 4. 指标口径

### 4.1 核心 KPI

| 指标 | 口径 | 建议来源 |
| --- | --- | --- |
| 活跃任务数 | 周期内状态为 `PUBLISHED` 或产生领取/提交的任务数 | `tasks`、`assignments`、`submissions` |
| 已领取数 | 周期内新增领取数 | `assignments.claimed_at` |
| 已提交数 | 周期内新增提交数 | `submissions` |
| 待审核数 | 当前待人工审核或待最终审核数量 | `submissions`、`review_tasks` |
| 通过率 | 周期内通过数 / 周期内已审核数 | `submissions.status`、`review_records` |
| 打回率 | 周期内打回数 / 周期内已审核数 | `submissions.status`、`review_records` |
| 奖励支出 | 周期内奖励发放金额汇总 | `reward_ledger`、`labeler_daily_stats` |

### 4.2 用户摘要

| 指标 | 口径 |
| --- | --- |
| 用户总数 | 非系统用户数量 |
| 角色分布 | ADMIN / OWNER / LABELER / REVIEWER 用户数 |
| 禁用账号数 | `enabled=false` 或 `login_enabled=false` 的用户数 |
| 最近新增用户 | 周期内创建的用户数 |

### 4.3 趋势数据

趋势按自然日聚合，返回周期内每天的数据点：

- 提交数。
- 通过数。
- 打回数。
- 奖励金额。

### 4.4 异常提醒

P0 异常提醒只做只读展示和跳转入口，不做自动处置。

建议异常类型：

| 类型 | 触发条件 |
| --- | --- |
| 审核积压 | 待审核数高于配置阈值，或存在超过 24 小时未审核提交 |
| 打回率偏高任务 | 周期内任务打回率高于平台平均值或固定阈值 |
| 零提交活跃任务 | 已发布且已领取，但周期内无提交 |
| 禁用账号提醒 | 存在禁用账号，支持跳转用户管理 |

阈值首版可以写死在后端服务层或配置中，需求默认：

- 审核积压阈值：待审核数 `>= 20`。
- 超时审核阈值：提交后超过 `24h` 未审核。
- 打回率偏高阈值：打回率 `>= 50%` 且已审核数 `>= 5`。

权限：

```text
ADMIN
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |

### 5.2 用户管理接口复用

管理端用户管理页继续复用现有接口：

```text
GET /api/v1/admin/users
POST /api/v1/admin/users/{userId}/enable
POST /api/v1/admin/users/{userId}/disable
POST /api/v1/admin/users/reviewers
PUT /api/v1/admin/users/{userId}/roles
```

看板首页只提供跳转和摘要，不重复实现用户管理操作。

## 6. 前后端协作边界

### 6.1 FE 负责

- 新增 `admin` 角色类型、路由和导航。
- 新增管理端数据看板页面。
- 新增用户管理页面入口或接入已有用户管理页面。
- 按接口响应渲染 KPI、趋势、分布、排行、异常提醒。
- 做好空状态、loading、错误提示和无权限兜底。

### 6.2 BE-A 负责

- 提供或协助聚合任务、领取、提交、审核、异常任务相关统计。
- 保证状态口径与现有任务、提交、审核状态机一致。
- 不为看板新增会改变业务状态的操作。

### 6.3 BE-B 负责

- 提供 Admin 看板聚合接口。
- 聚合用户、角色、奖励、贡献、审计等平台支撑数据。
- 复用现有 Admin 用户管理能力。
- 保证接口只允许 `ADMIN` 访问。

## 7. 验收标准

### 7.1 权限验收

- ADMIN 登录后可以看到管理端导航和数据看板。
- OWNER、LABELER、REVIEWER 看不到管理端入口。
- 非 ADMIN 直接访问管理端接口返回 `403001`。
- 未登录访问返回 `401001` 或前端跳转登录页。

### 7.2 数据验收

- 默认展示近 7 天数据。
- 切换近 30 天后，KPI、趋势、排行和异常提醒都同步刷新。
- 无数据时页面不报错，展示 0 值和空状态。
- 奖励摘要只展示汇总金额，不展示完整奖励流水。
- 用户管理摘要与用户管理列表数据口径一致。

### 7.3 页面验收

- 首屏能看到核心 KPI。
- 趋势图、分布图、排行、异常提醒在同一页面内完成展示。
- 点击用户管理入口能进入用户管理页。
- 首页不直接提供启用、禁用、改角色等高风险操作按钮。

## 8. 后续扩展

后续可以基于同一角色看板体系继续补充：

- Owner 数据看板：任务质量、任务进度、导出和奖励成本。
- Labeler 数据看板：个人提交、通过率、打回、贡献和奖励。
- Reviewer 数据看板：审核队列、审核效率、通过/打回、AI 复核情况。
- 管理端二期：审计中心、财务报表、异常治理工作台、自定义日期范围。

扩展原则：

- OWNER、LABELER、REVIEWER 只能访问自己权限范围内的数据；ADMIN 可跨角色访问业务数据。
- 角色看板共用页面布局规范，但接口和数据口径按角色隔离。
- 涉及状态推进的操作必须回到对应业务模块，不在看板中绕过原有权限和状态机。
