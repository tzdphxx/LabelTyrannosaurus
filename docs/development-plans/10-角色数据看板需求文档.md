# 10-角色数据看板需求文档

> 面向 FE、BE-A、BE-B 与 AI 开发工具：本文档定义 LabelHub 角色数据看板体系中 `OWNER`、`LABELER`、`REVIEWER` 三类业务角色的数据看板首版需求。`ADMIN` 管理端数据看板见 `09-管理端数据看板需求文档.md`，本文不重复展开管理端能力。

## 0. 文档目标

当前平台已经具备任务创建、任务领取、标注提交、人工审核、AI 审核、奖励贡献统计和导出审计等业务能力。现有三类业务角色都有工作台入口：

```text
/app/owner
/app/labeler
/app/reviewer
```

但首版工作台能力不均衡：Owner 首页已有基础任务摘要，Labeler 和 Reviewer 首页仍偏占位或轻量入口；用户登录后缺少按角色聚合的数据总览，无法快速回答“我现在最需要关注什么”。

本需求目标是将三类业务角色首页升级为角色专属数据看板，让用户登录后在各自首页看到和当前职责直接相关的数据摘要、趋势、待关注项和业务入口。

首版定位：

- 角色工作台升级，不新增独立报表中心。
- 三类角色看板展示内容必须不同，围绕各自职责设计。
- 看板首页只做只读摘要和跳转入口，不直接执行会改变业务状态的操作。
- 每类角色提供一个聚合 overview 接口，前端首页优先消费聚合接口。
- OWNER、LABELER、REVIEWER 只能访问自己权限范围内的数据，不能互相读取。

## 1. 范围边界

### 1.1 P0 范围

P0 必须交付：

- `OWNER`、`LABELER`、`REVIEWER` 三类角色首页数据看板。
- 三类看板沿用现有路由和导航入口。
- 三类看板各自独立的指标口径、页面模块和聚合接口草案。
- 看板 loading、错误、空状态和无权限兜底。
- 页面跳转入口，连接到现有任务管理、任务广场、我的提交、审核队列、审核历史等业务页面。

### 1.2 P0 不做

P0 不做以下能力：

- 不新增 `/dashboard` 子路由作为独立报表中心。
- 不在看板首页直接领取任务、提交标注、审核通过、审核打回、暂停任务、结束任务或删除任务。
- 不实现跨角色排行、绩效考核、财务对账或复杂运营分析。
- 不支持复杂自定义日期范围。
- 不允许普通业务角色查看其他用户或其他角色的数据。
- 不替代现有业务页面的筛选、分页、编辑和状态流转能力。

## 2. 用户与角色目标

### 2.1 OWNER 看板目标

目标用户为任务负责人 `OWNER`。

Owner 看板首版重点回答：

- 我创建的任务整体交付进度如何？
- 哪些任务已经发布但推进慢？
- 哪些任务卡在审核或存在异常？
- 当前任务质量是否稳定？
- 奖励成本是否在可接受范围内？
- 是否需要进入任务管理、模板管理或导出审计继续处理？

Owner 看板以任务交付进度为主，质量和奖励成本只做辅助摘要。

### 2.2 LABELER 看板目标

目标用户为标注员 `LABELER`。

Labeler 看板首版重点回答：

- 我近期领取、提交和通过了多少？
- 我的通过率、打回情况和奖励收益如何？
- 哪些任务贡献最多？
- 是否存在被打回或需要继续处理的提交？
- 是否需要进入任务广场、标注工作台或我的提交？

Labeler 看板以个人产出与收益为主，待办和返工作为提醒入口。

### 2.3 REVIEWER 看板目标

目标用户为审核员 `REVIEWER`。

Reviewer 看板首版重点回答：

- 我当前待审队列压力如何？
- 今天已经审核了多少？
- 是否存在超时待审或需要优先处理的提交？
- 我的通过、打回和审核趋势如何？
- AI 复核是否有需要关注的异常？
- 是否需要进入审核队列或审核历史？

Reviewer 看板以审核队列压力为主，效率质量和 AI 复核只做辅助摘要。

## 3. 权限规则

- `OWNER` 只能访问 Owner 看板，只能查看当前登录 Owner 自己创建的任务及相关统计。
- `LABELER` 只能访问 Labeler 看板，只能查看当前登录 Labeler 自己的领取、提交、贡献和奖励数据。
- `REVIEWER` 只能访问 Reviewer 看板，只能查看当前登录 Reviewer 可处理或分配给自己的审核数据。
- 未登录访问任一看板接口时，后端返回 `401001`，前端跳转登录页或展示登录态失效提示。
- 角色不匹配访问任一看板接口时，后端返回 `403001`，前端不展示对应导航入口。
- 首页跳转到业务页面后，继续遵循对应业务接口既有权限规则。

### 3.1 统一统计口径

- 首版看板以实时聚合为主，不把未持续维护的汇总表作为行为指标主口径。
- Owner 的领取、提交、待审、通过、打回和进度数据从 `tasks`、`assignments`、`submissions`、`review_tasks` 实时聚合，不依赖 `task_stats`。
- Labeler 的领取、提交、打回、待处理返工等行为指标从 `assignments`、`submissions` 实时聚合；`labeler_contribution_stats`、`labeler_daily_stats`、`labeler_task_stats` 只可作为已确认维护的通过数、奖励金额等辅助来源，不能作为提交数、打回数、待审数的唯一来源。
- Reviewer 的待审可见范围复用现有审核队列规则：`submissions.assigned_reviewer_id = currentUserId` 或 `review_tasks.assigned_reviewer_id = currentUserId`；首版不依赖额外 reviewer-task 关系表扩展可见范围。
- 奖励金额统一使用净额口径：`CREDIT - DEBIT`。如果页面需要展示毛发放额，字段名必须显式使用 `grossReward` 或 `grossRewardCost`，不能复用 `reward`、`periodReward`、`totalReward`、`rewardCost` 等默认字段。
- `approvalRate`、`rejectionRate` 等比率字段统一返回 `0.0000 ~ 1.0000` 小数；分母为 0 时返回 `0`。
- 无数据场景下，所有计数和金额返回 0，趋势按日期补 0，列表返回空数组。

## 4. 路由与导航

三类角色看板沿用现有工作台路由：

| 角色 | 首页路由 | 导航名称 | 首页定位 |
| --- | --- | --- | --- |
| OWNER | `/app/owner` | 工作台 | 任务交付进度看板 |
| LABELER | `/app/labeler` | 工作台 | 个人产出与收益看板 |
| REVIEWER | `/app/reviewer` | 工作台 | 审核队列压力看板 |

首版不新增以下路由：

```text
/app/owner/dashboard
/app/labeler/dashboard
/app/reviewer/dashboard
```

页面入口规则：

- Owner 看板可跳转 `/app/owner/tasks`、`/app/owner/templates`、`/app/owner/audit`。
- Labeler 看板可跳转 `/app/labeler/market`、`/app/labeler/submissions`，继续标注时跳转具体 `/app/labeler/workbench/:taskId`。
- Reviewer 看板可跳转 `/app/reviewer/queue`、`/app/reviewer/history`，查看详情时跳转 `/app/reviewer/tasks/:reviewId`。

## 5. 页面需求

### 5.1 OWNER 首页线框

```text
+--------------------------------------------------------------------------------+
| 任务负责人工作台                                      [近30天趋势] [刷新]       |
+--------------------------------------------------------------------------------+
| 总任务数 | 进行中任务 | 已领取题目 | 已提交题目 | 待审核 | 通过率 | 奖励成本     |
+--------------------------------------------------------------------------------+
| 任务交付趋势折线图                         | 任务状态分布                       |
| - claimed_count                            | - DRAFT/PUBLISHED/PAUSED/ENDED     |
| - submitted_count                          |                                      |
| - approved_count                           |                                      |
+--------------------------------------------------------------------------------+
| 待关注任务                                  | 质量与成本摘要                      |
| - 发布后低领取任务                          | - 通过率                            |
| - 审核积压任务                              | - 打回率                            |
| - 长时间无提交任务                          | - 奖励成本                          |
+--------------------------------------------------------------------------------+
| 最近任务：任务标题 / 状态 / 完成率 / 待审核数 / 最近更新时间       [任务管理]   |
+--------------------------------------------------------------------------------+
```

Owner 交互规则：

- 首页主口径为当前 Owner 的全部自有任务。
- 趋势数据固定展示近 30 天，首版不提供自定义日期范围。
- 点击任务管理进入 `/app/owner/tasks`。
- 点击具体任务进入任务详情或编辑页，具体路径复用现有任务页面规则。
- 首页不直接提供发布、暂停、结束、删除任务按钮。

### 5.2 LABELER 首页线框

```text
+--------------------------------------------------------------------------------+
| 标注员工作台                                            [近7天/近30天] [刷新]  |
+--------------------------------------------------------------------------------+
| 已领取 | 已提交 | 已通过 | 被打回 | 通过率 | 累计奖励 | 待处理返工             |
+--------------------------------------------------------------------------------+
| 个人贡献趋势折线图                         | 任务贡献排行                       |
| - submitted_count                          | - task_title                       |
| - approved_count                           | - submitted/approved               |
| - reward                                   | - total_reward                     |
+--------------------------------------------------------------------------------+
| 待关注提醒                                  | 收益摘要                            |
| - 被打回提交                                | - 周期奖励                          |
| - 已领取未提交任务                          | - 累计奖励                          |
| - 可继续作答任务                            | - 奖励可见性说明                    |
+--------------------------------------------------------------------------------+
| 快捷入口：任务广场 / 我的提交 / 继续标注                                      |
+--------------------------------------------------------------------------------+
```

Labeler 交互规则：

- 默认展示近 30 天贡献数据。
- 支持切换近 7 天和近 30 天。
- 切换后 KPI、趋势、任务贡献排行、提醒同步刷新。
- 点击任务广场进入 `/app/labeler/market`。
- 点击我的提交进入 `/app/labeler/submissions`。
- 点击继续标注进入对应 `/app/labeler/workbench/:taskId`。
- 首页不直接领取任务、不直接提交答案、不直接修改被打回提交。

### 5.3 REVIEWER 首页线框

```text
+--------------------------------------------------------------------------------+
| 审核员工作台                                            [近7天/近30天] [刷新]  |
+--------------------------------------------------------------------------------+
| 当前待审 | 超时待审 | 今日已审 | 累计通过 | 累计打回 | 通过率 | AI需关注        |
+--------------------------------------------------------------------------------+
| 审核趋势折线图                             | 队列压力分布                       |
| - reviewed_count                           | - pending_final                    |
| - approved_count                           | - manual_required                  |
| - rejected_count                           | - conflict_required                |
+--------------------------------------------------------------------------------+
| 待关注提交                                  | AI 复核摘要                         |
| - 超时待审                                  | - AI建议通过                        |
| - 冲突待处理                                | - AI建议打回                        |
| - 需人工复核                                | - 人工改判                          |
+--------------------------------------------------------------------------------+
| 最近审核记录：任务 / 提交人 / 结果 / 审核时间                      [审核队列] |
+--------------------------------------------------------------------------------+
```

Reviewer 交互规则：

- 首页主口径为当前待审队列和今日已审数据。
- 默认趋势展示近 7 天，可切换近 30 天。
- 切换后趋势、辅助摘要和最近审核记录同步刷新。
- 点击审核队列进入 `/app/reviewer/queue`。
- 点击审核历史进入 `/app/reviewer/history`。
- 点击待关注提交进入审核详情页。
- 首页不直接展示通过、打回、分配审核员等操作按钮。

## 6. 指标口径

### 6.1 OWNER 核心指标

| 指标 | 口径 | 建议来源 |
| --- | --- | --- |
| 总任务数 | 当前 Owner 创建的全部任务数 | `tasks.owner_id` |
| 进行中任务 | 状态为 `PUBLISHED` 或 `PAUSED` 且未结束的任务数 | `tasks.status` |
| 已领取题目 | 当前 Owner 任务下累计领取数量 | `assignments` |
| 已提交题目 | 当前 Owner 任务下累计提交数量 | `submissions` |
| 待审核数 | 当前 Owner 任务下待人工审核或待最终审核数量 | `submissions`、`review_tasks` |
| 通过率 | 当前 Owner 任务下已通过数 / 已审核数 | `submissions.status`、`review_records` |
| 奖励成本 | 当前 Owner 任务下已发放奖励净额，`CREDIT - DEBIT` | `reward_ledger` |

Owner 待关注任务：

| 类型 | 触发条件 |
| --- | --- |
| 低领取任务 | 已发布但领取率低于配置阈值 |
| 审核积压任务 | 待审核数高于配置阈值 |
| 长时间无提交任务 | 已发布且存在领取，但近 24 小时无新增提交 |
| 高打回率任务 | 已审核数达到阈值且打回率偏高 |

首版默认阈值：

- 低领取阈值：领取率 `< 20%` 且任务已发布超过 `24h`。
- 审核积压阈值：单任务待审核数 `>= 10`。
- 无提交阈值：近 `24h` 无新增提交。
- 高打回率阈值：打回率 `>= 50%` 且已审核数 `>= 5`。

### 6.2 LABELER 核心指标

| 指标 | 口径 | 建议来源 |
| --- | --- | --- |
| 已领取数 | 当前 Labeler 周期内或累计领取数量 | `assignments` |
| 已提交数 | 当前 Labeler 周期内提交数量 | `submissions` |
| 已通过数 | 当前 Labeler 周期内通过数量 | `submissions.status`；统计表仅可作为辅助校验 |
| 被打回数 | 当前 Labeler 周期内打回数量 | `submissions.status` |
| 通过率 | 通过数 / 已审核数，待审核不进入分母 | `submissions.status` |
| 周期奖励 | 周期内奖励净额，`CREDIT - DEBIT` | `reward_ledger` |
| 累计奖励 | 当前 Labeler 累计奖励净额，`CREDIT - DEBIT` | `reward_ledger`；统计表仅可作为辅助校验 |
| 待处理返工 | 当前 Labeler 被打回且可修改的提交数 | `assignments`、`submissions` |

Labeler 任务贡献排行：

- 按任务聚合当前 Labeler 的提交数、通过数和奖励金额。
- 默认展示前 5 个任务。
- 无贡献时展示空状态。

Labeler 待关注提醒：

| 类型 | 触发条件 |
| --- | --- |
| 被打回提交 | 存在 `REJECTED` 且可重新提交的记录 |
| 已领取未提交 | 存在已领取但未提交的 assignment |
| 近期无提交 | 近 7 天提交数为 0 |
| 奖励不可见 | 当前任务奖励未开放给标注员查看 |

### 6.3 REVIEWER 核心指标

| 指标 | 口径 | 建议来源 |
| --- | --- | --- |
| 当前待审数 | 分配给当前 Reviewer 的待审任务，或当前 Reviewer 在现有审核队列规则下可处理的 `PENDING_FINAL` 提交数 | `submissions.assigned_reviewer_id`、`review_tasks.assigned_reviewer_id` |
| 超时待审数 | 提交后超过阈值仍未审核的数量 | `submissions.submitted_at` |
| 今日已审数 | 当前 Reviewer 当日完成审核记录数 | `review_records` |
| 累计通过数 | 当前 Reviewer 累计审核通过数量 | `review_records.action` |
| 累计打回数 | 当前 Reviewer 累计审核打回数量 | `review_records.action` |
| 通过率 | 通过数 / 已审核数 | `review_records` |
| AI 需关注 | AI 结论为需人工复核、冲突或人工改判的数量 | `ai_review_results`、`conflict_groups` |

Reviewer 待关注项：

| 类型 | 触发条件 |
| --- | --- |
| 超时待审 | 待审提交超过 `24h` 未处理 |
| 冲突待处理 | 存在冲突组或需最终裁决记录 |
| AI 需人工复核 | AI 审核状态要求人工处理 |
| 高风险打回 | 同一任务近期打回率偏高 |

## 8. 前后端协作边界

### 8.1 FE 负责

- 将 `/app/owner`、`/app/labeler`、`/app/reviewer` 首页升级为对应角色看板。
- 按角色渲染不同 KPI、趋势、待关注项和业务入口。
- 接入三个 overview 聚合接口。
- 处理 loading、错误、空状态和无权限兜底。
- 首页所有按钮只做跳转，不直接调用状态变更接口。
- 保持现有导航结构和角色入口不变。

### 8.2 BE-A 负责

- 提供或协助聚合任务交付、领取、提交、审核、AI 复核、冲突处理等业务统计。
- 保证任务、提交、审核、AI 复核状态口径与现有状态机一致。
- 不为看板新增绕过业务流程的状态变更接口。

### 8.3 BE-B 负责

- 提供三类角色看板 overview 聚合接口。
- 聚合用户上下文、奖励贡献、任务归属、权限隔离和基础支撑数据。
- 复用现有贡献、奖励、用户身份和审计能力。
- 保证接口按当前登录用户隔离数据，不接受前端传入 ownerId、labelerId 或 reviewerId 来越权查询。

## 9. 空状态与异常状态

### 9.1 通用空状态

- 无任务、无提交、无审核、无奖励时，KPI 展示 `0`。
- 趋势图无数据时展示空折线或空状态，不报错。
- 排行、待关注项为空时展示“暂无需要关注的数据”。
- 接口返回部分列表为空时，页面其他模块仍正常展示。

### 9.2 通用加载与错误

- 首次加载展示骨架屏或卡片 loading。
- 点击刷新时只刷新当前看板数据，不改变当前时间范围。
- 接口返回 `401001` 时跳转登录页或提示登录已失效。
- 接口返回 `403001` 时展示无权限兜底页。
- 接口返回 `400001` 时回退默认查询参数并展示参数错误提示。

## 10. 验收标准

### 10.1 权限验收

- OWNER 登录后可以看到 Owner 数据看板，看不到 Labeler、Reviewer 看板入口。
- LABELER 登录后可以看到 Labeler 数据看板，看不到 Owner、Reviewer 看板入口。
- REVIEWER 登录后可以看到 Reviewer 数据看板，看不到 Owner、Labeler 看板入口。
- 三类角色互相直接访问非本角色看板接口时返回 `403001`。
- 未登录访问任一看板接口时返回 `401001`。
- 接口数据不允许通过传入其他用户 ID 越权读取。

### 10.2 数据验收

- Owner 看板任务数、状态分布、待审核数、通过率与当前 Owner 自有任务数据一致。
- Owner 最近任务进度和待审核数从实时业务表聚合，不能依赖未维护的 `task_stats`。
- Labeler 看板领取、提交、打回、返工提醒与当前 Labeler 的 `assignments`、`submissions` 一致。
- Labeler 奖励字段按 `reward_ledger` 净额口径展示，存在冲正流水时不会展示毛发放额。
- Reviewer 看板待审数、今日已审、通过率与当前 Reviewer 审核记录一致。
- Reviewer 待审、冲突和 AI 需关注数据只来自当前 Reviewer 被分配或现有队列规则可见的数据，不依赖额外 reviewer-task 关系表。
- 近 7 天和近 30 天切换后，Labeler、Reviewer 的 KPI、趋势和列表同步刷新。
- Owner 趋势使用近 30 天默认口径，刷新后数据保持同一口径。
- 无数据场景页面不报错，展示 0 值和空状态。

### 10.3 页面验收

- 三类角色首页首屏都能看到核心 KPI。
- 三类角色看板展示模块明显不同，不能复用同一套指标文案。
- 首页待关注项可跳转到对应业务页面。
- 首页不直接展示领取、提交、审核通过、审核打回、暂停、结束、删除等状态变更按钮。
- 点击刷新会重新请求当前角色看板聚合接口。

### 10.4 接口验收

- `GET /api/v1/owner/dashboard/overview` 仅允许 OWNER 访问。
- `GET /api/v1/labeler/dashboard/overview` 仅允许 LABELER 访问。
- `GET /api/v1/reviewer/dashboard/overview` 仅允许 REVIEWER 访问。
- `range` 只接受 `7d`、`30d`。
- `trendDays` 只接受 `7`、`30`。
- 非法参数返回 `400001`。

## 11. 后续扩展

后续可以在不改变首版首页定位的前提下扩展：

- Owner 二期：任务预算预警、导出进度、任务质量对比、模板复用效果。
- Labeler 二期：奖励流水明细、个人能力标签、任务推荐、质量提升建议。
- Reviewer 二期：审核耗时、审核一致性、人工改判分析、冲突治理工作台。
- 统一二期：自定义日期范围、导出报表、图表下钻、移动端适配优化。

扩展原则：

- 新增能力必须继续遵循角色数据隔离。
- 涉及状态推进的操作仍回到原业务模块。
- 财务、绩效、治理类能力应作为二期独立设计，不塞入 P0 首页。
