# LabelHub 前端需求说明

## 1. 文档目标

本文档将 `demand.md` 中的全栈课题要求，收敛为一份只面向前端实现的需求说明。目标不是复述后端能力，而是明确前端必须交付什么、页面怎么组织、关键交互怎么跑通、哪些状态必须被看见，以及前端验收时看什么。

## 2. 产品定位

LabelHub 是一个面向数据标注全生命周期的 Web 平台，前端需要覆盖以下三个核心工作面：

- 任务负责人侧：创建任务、搭建标注模板、配置审核规则、分发数据、查看质量与导出结果。
- 标注员侧：领取任务、在线作答、草稿保存、查看打回原因并修改、提交标注结果。
- 审核员侧：查看待审队列、执行多级审核、批量处理、回看 AI 预审结果与审计记录。

前端的核心难点不在静态页面，而在“动态表单 + schema 渲染 + 多角色工作流 + AI 结果可视化”的组合。

## 3. 设计原则

- 以工作台思维组织界面，信息密度高但层级清晰。
- 所有核心流程必须可追踪、可回看、可恢复。
- Schema 驱动的页面必须支持预览态和运行态一致。
- 复杂操作优先用显式状态、清晰反馈和可撤销交互。
- 所有角色页面都要保留空态、加载态、错误态、无权限态。

## 4. 前端范围

### 4.1 任务负责人侧

前端需支持以下页面与能力：

- 任务创建与编辑
- 标注模板搭建
- 审核规则配置
- 数据集导入与预览
- 任务发布与下发
- 质量结果查看
- 导出任务结果与审计记录

### 4.2 标注员侧

前端需支持以下页面与能力：

- 任务广场/任务列表
- 任务领取
- 标注工作台
- 草稿保存
- 提交前校验
- 打回后修改
- 我的任务统计与历史

### 4.3 审核员侧

前端需支持以下页面与能力：

- 审核任务队列
- 审核详情页
- 多级审核处理
- 批量审核操作
- 审核结果与原因回看
- 审计日志查看

## 5. 页面结构

### 5.1 通用框架

- 顶部全局栏：项目切换、当前角色、通知、个人入口
- 左侧导航：按角色动态展示菜单
- 主工作区：列表页、详情页、编辑页、审核页
- 统一右侧抽屉/面板：属性编辑、规则配置、辅助信息

### 5.2 Owner 页面

- 仪表盘：任务数、进行中、待审核、异常数据、导出任务
- 任务管理：列表、筛选、状态、批量操作
- 模板管理：创建、复制、版本对比、预览
- 数据管理：导入、字段映射、样本预览、错误提示
- 发布配置：分发策略、领取方式、截止时间、奖励规则
- 审计与导出：导出历史、任务链路、操作日志

### 5.3 Labeler 页面

- 任务广场：搜索、筛选、卡片/表格展示
- 工作台：schema 渲染表单、题目预览、提交区
- 我的数据：已提交、通过、打回、待修改

### 5.4 Reviewer 页面

- 审核队列：待审、进行中、已完成、异常
- 审核详情：原始数据、标注结果、AI 预审结论、操作记录
- 审核操作：通过、打回、修订、批量处理

## 6. 核心交互

### 6.1 动态表单搭建

模板搭建必须支持拖拽式编辑，并具备以下能力：

- 左侧物料区，中间画布区，右侧属性区
- 组件拖拽、排序、分组、嵌套
- schema 实时预览
- 预览态与运行态一致
- 配置项即时生效，支持撤销/重做

### 6.2 Schema 驱动渲染

前端需要将“字段定义”与“渲染组件”解耦，至少覆盖：

- 单行输入、多行输入
- 单选、多选、标签选择
- 富文本编辑
- 文件/图片上传
- JSON 编辑器
- LLM 交互组件
- 展示项 ShowItem

### 6.3 字段联动与校验

- 支持条件显隐
- 支持联动校验
- 支持必填、长度、正则、自定义函数
- 支持提交前整体校验与局部校验提示

### 6.4 标注工作流

标注员工作流必须支持：

- 领取任务
- 进入工作台
- 草稿自动保存
- 上一题 / 下一题 / 跳题
- 提交前校验
- 查看打回原因
- 重新提交

### 6.5 AI 预审可视化

前端要清楚展示 AI 预审链路，不只显示最终结论，还要显示：

- 评分维度
- 每个维度的分值
- 预审建议
- 通过 / 打回 / 人工复核结果
- 原始 Prompt 与返回结果的审计痕迹

### 6.6 导出与历史

- 支持多格式导出：JSON、JSONL、CSV、Excel
- 支持异步导出任务
- 支持导出历史与任务进度查询
- 支持字段映射配置

## 7. 状态与权限

### 7.1 任务状态

- 草稿
- 发布中
- 已暂停
- 已结束
- 待领取
- 进行中
- 已提交
- 待审核
- 已通过
- 已打回

### 7.2 权限要求

前端必须按角色控制：

- 菜单可见性
- 页面入口可见性
- 按钮级操作可见性
- 数据字段可见性
- 审计记录可见性

## 8. 技术实现建议

当前仓库已使用 `React 19 + Vite + TypeScript`，因此前端需求说明应保持与该技术基线兼容。

推荐的实现方向：

- 表单与 schema 渲染：优先采用可配置 schema 模型
- 拖拽编排：优先采用成熟拖拽能力
- 状态管理：集中管理任务、表单草稿、权限与审核流状态
- 请求层：统一封装列表、详情、提交、导出、日志接口

如果后续要进一步落地，建议优先补齐可复用的表单模型、工作流状态模型和审计日志模型。

## 9. 验收标准

前端视角的验收标准应至少覆盖：

- 任务负责人可完成“建任务 - 搭模板 - 发布 - 预览 - 导出”闭环
- 标注员可完成“领任务 - 作答 - 草稿 - 提交 - 修改”闭环
- 审核员可完成“待审 - 审核 - 批量处理 - 查看原因”闭环
- AI 预审结果可被清晰查看并追溯
- 导出任务与历史记录可查询
- 关键页面在空态、异常态、加载态下行为一致

## 10. 建议配置的 Skills

建议后续补充以下 skills：

- `frontend-design`：用于复杂工作台、动态表单、密集信息界面的前端设计与落地。
- `openai-docs`：用于 AI 预审、Prompt 配置、结构化输出等 OpenAI 相关接入说明。
- `skill-creator`：用于把 LabelHub 的 schema 搭建、审核流、导出流程整理成可复用的专用技能。
