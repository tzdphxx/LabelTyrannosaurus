# 阶段一：基础可跑

## 目标

建立项目的前端基础设施，让应用先具备“能登录、能识别角色、能进入对应工作台、能承接后续业务模块”的最小可用形态。

阶段一最终效果：

- 应用默认进入登录页
- 用户可选择任务负责人、标注员、审核员三种身份登录
- 不同身份登录后进入不同角色页面
- 顶部导航栏和侧边导航栏抽离为公共组件
- 登录态、角色、导航和页面基础状态由统一状态管理承载

## 依赖安装

本阶段需要新增以下依赖，由开发者手动执行安装，不写入 P0/P1 执行步骤。

```bash
npm install react-router zustand antd @ant-design/icons
```

依赖用途：

- `react-router`：应用路由、登录跳转、角色页面守卫
- `zustand`：登录态、当前角色、导航状态和页面 UI 状态管理
- `antd`：工作台布局、菜单、按钮、表单、结果页等基础 UI
- `@ant-design/icons`：顶部导航和侧边导航中的图标

## 覆盖任务

- 任务 1：初始化前端目录结构
- 任务 2：建立登录入口、全局布局、角色导航、权限守卫
- 任务 3：抽离顶部导航栏和侧边导航栏公共组件
- 任务 4：建立登录态、角色、导航和页面状态管理
- 任务 5：定义阶段一需要的核心类型

## P0 - 必须先完成

### P0.1 目录与工程骨架

建立并固定阶段一需要的目录：

```text
src/
  app/
  pages/
  components/
  stores/
  types/
  hooks/
  utils/
```

目录职责：

- `app`：路由、应用布局、权限守卫
- `pages`：登录页和三类角色首页
- `components`：公共导航、状态展示、页面壳组件
- `stores`：Zustand 状态切片
- `types`：角色、用户、导航、页面状态类型
- `hooks`：读取登录态、角色权限、当前导航的通用 hooks
- `utils`：角色跳转、菜单匹配等纯函数

阶段一先不建立 `services` 服务层骨架，不实现 API Client，也不接入 Mock 业务数据。

### P0.2 登录入口

实现最小可运行的登录页：

- 登录页提供三个身份入口：任务负责人、标注员、审核员
- 每个身份对应一个默认演示账号
- 点击身份后写入当前用户、当前角色和登录状态
- 登录成功后跳转到对应角色首页
- 退出登录后清空登录状态并回到登录页

默认角色跳转关系：

- 任务负责人：`/app/owner`
- 标注员：`/app/labeler`
- 审核员：`/app/reviewer`

### P0.3 路由与权限守卫

建立阶段一最小路由：

- `/login`
- `/app/owner`
- `/app/labeler`
- `/app/reviewer`

路由行为：

- 未登录访问 `/app/*` 时跳转到 `/login`
- 已登录访问 `/login` 时跳转到当前角色首页
- 已登录用户访问非当前角色页面时，重定向到自己的角色首页
- 未匹配路由进入统一空态或重定向到合理入口

### P0.4 公共布局组件

抽离并复用公共布局：

- `TopNav`：顶部导航栏，展示产品名、当前角色、当前用户、退出入口
- `SideNav`：侧边导航栏，根据当前角色展示不同菜单
- `AppLayout`：组合顶部导航栏、侧边导航栏和主内容区

布局要求：

- 三类角色页面共用同一套 `TopNav`、`SideNav` 和 `AppLayout`
- 页面内部不重复实现顶部栏和侧边栏
- 侧边栏菜单由角色配置驱动，不在组件内硬编码多个分支
- 主内容区预留后续业务页面承载空间

### P0.5 核心类型

先定义阶段一需要的基础类型：

- `Role`：`owner | labeler | reviewer`
- `User`：用户 id、名称、角色
- `AuthState`：当前用户、当前角色、是否已登录、登录错误
- `NavItem`：菜单 id、标题、路径、图标、角色
- `PageState`：加载态、空态、错误态、无权限态

暂不定义任务、模板、提交、审核、导出等完整业务类型，避免阶段一引入过早复杂度。

## P1 - 稳定基础

### P1.1 状态管理

使用 Zustand 建立清晰的状态切片。

`authStore` 负责登录态：

- `currentUser`：当前登录用户
- `currentRole`：当前角色
- `isAuthenticated`：是否已登录
- `loginError`：登录失败原因
- `loginAsRole(role)`：按角色登录演示账号
- `logout()`：退出登录并清空状态
- `getRoleHomePath()`：返回当前角色首页路径

`navigationStore` 负责导航状态：

- `collapsed`：侧边栏是否折叠
- `activePath`：当前激活路径
- `activeMenuKey`：当前激活菜单项
- `setCollapsed(collapsed)`：切换侧边栏折叠状态
- `setActivePath(path)`：同步当前路由路径

`permissionStore` 或权限工具函数负责角色判断：

- 判断当前角色是否允许访问目标路径
- 根据角色过滤侧边栏菜单
- 为无权限页面提供统一判断结果

`pageUiStore` 负责页面基础状态：

- `loading`：页面级加载态
- `empty`：页面级空态
- `errorMessage`：页面级错误信息
- `forbidden`：页面级无权限状态
- 提供设置和重置页面状态的方法

状态管理约束：

- 登录态是角色判断的唯一来源
- 角色首页跳转只从统一配置读取，不在页面中散落硬编码
- 导航高亮由当前路由推导或同步，不由页面组件各自维护
- 阶段一不持久化登录态，刷新后回到登录页

### P1.2 角色菜单与角色首页

完善三类角色的最小页面入口。

任务负责人菜单：

- 工作台：`/app/owner`
- 任务管理：预留入口
- 模板管理：预留入口
- 导出与审计：预留入口

标注员菜单：

- 工作台：`/app/labeler`
- 任务广场：预留入口
- 我的提交：预留入口

审核员菜单：

- 工作台：`/app/reviewer`
- 审核队列：预留入口
- 审核历史：预留入口

三类角色首页只展示阶段一必要信息：

- 当前角色名称
- 当前用户信息
- 该角色后续核心工作入口说明
- 基础空态或占位内容

### P1.3 共享基础组件

补齐后续会复用的基础组件：

- `PageHeader`：页面标题和辅助说明
- `StatePlaceholder`：统一空态、错误态、无权限态
- `RoleBadge`：当前角色展示
- `ContentShell`：主内容区域基础容器

组件要求：

- 不做冗杂大文件，公共组件按职责拆分
- 不把角色业务内容写死在布局组件中
- 不引入和阶段一无关的复杂表格、抽屉、表单封装

### P1.4 主题与交互规范

统一基础工作台体验：

- 使用 Ant Design 的 `Layout`、`Menu`、`Button`、`Card`、`Result` 等基础组件
- 顶部导航高度、侧边栏宽度、主内容边距保持一致
- 登录页三种身份入口视觉一致
- 退出登录有明确入口
- 无权限、错误、空态使用统一组件展示

## 产出

- 项目可启动
- 默认进入登录页
- 三类身份可登录到对应角色页面
- 顶部导航栏和侧边导航栏已抽离为公共组件
- 不同角色看到不同侧边导航
- 非本角色页面不可直接访问
- 登录态、角色、导航和页面状态由 Zustand 管理
- 阶段一不包含服务层骨架和业务 Mock 数据

## 验收标准

- 应用默认展示 `/login`
- 任务负责人登录后进入 `/app/owner`
- 标注员登录后进入 `/app/labeler`
- 审核员登录后进入 `/app/reviewer`
- 退出登录后回到 `/login`
- 未登录访问 `/app/*` 会回到 `/login`
- 已登录用户访问其他角色页面时不会看到对方页面内容
- `TopNav`、`SideNav`、`AppLayout` 被三类角色页面复用
- 侧边导航按当前角色动态展示
- `npm run build` 通过
- `npm run lint` 通过

## 风险

- 当前认证仅为前端演示态，后续需要替换为真实认证接口
- 阶段一不持久化登录态，刷新后回到登录页
- 权限模型当前按角色控制，后续再细化到按钮级和字段级
- 阶段一不建立服务层，后续接接口时需要单独规划 API Client 和 service 目录
