# 阶段二：Owner 闭环

## 目标

让任务负责人完成从任务总览、任务创建、数据导入、任务管理到发布的基础闭环，并补齐阶段一遗留的业务数据、服务层与 Mock 数据基础能力。

## 覆盖任务

- 任务 6：任务负责人仪表盘
- 任务 7：任务管理
- 任务 8：任务创建/编辑
- 任务 9：数据集导入与预览

## P0：Owner 闭环最小可用

### 1. 服务层与 Mock 数据基础

建立 Owner 阶段的业务数据访问边界：

- 新增 `src/services/owner/`，承载 Owner 阶段业务服务。
- 新增 `src/mocks/`，按数据类型拆分 Mock 数据文件。
- 页面组件只能通过服务层读取业务数据，不能直接引用 Mock 数据。
- 服务方法全部保持异步调用形态，便于后续替换为真实 API Client。

建议结构：

```text
src/
  services/
    owner/
      ownerDashboardService.ts
      ownerTaskService.ts
      ownerImportService.ts
    index.ts
  mocks/
    ownerDashboard.mock.ts
    tasks.mock.ts
    templates.mock.ts
    imports.mock.ts
    index.ts
  types/
    task.ts
    template.ts
    import.ts
```

Mock 数据至少覆盖：

- 任务数据：任务列表、任务详情、任务状态。
- 任务进度数据：总数据量、已分发量、已完成量、待审核量、通过量、驳回量。
- 模板数据：可关联模板、模板基础信息。
- 数据集数据：导入样本、字段映射、导入错误。
- 仪表盘数据：统计卡片、最近任务、异常数量。

服务层至少提供：

- 任务列表查询
- 任务详情查询
- 任务创建
- 任务编辑
- 任务状态切换
- 仪表盘统计查询
- 导入预览查询

### 2. Owner 状态管理

P0 需要建立 Owner 业务状态，不应只依赖页面局部 state。

新增 `ownerTaskStore`，承载跨页面共享的任务状态：

- 任务列表数据
- 当前选中的任务详情
- 当前选中任务进度
- 任务列表筛选条件
- 任务列表加载状态
- 任务详情加载状态
- 任务进度加载状态
- 任务状态操作提交状态
- 最近一次业务错误信息

新增 `ownerDraftStore`，承载任务创建与编辑草稿状态：

- 当前草稿任务基础信息
- 当前草稿关联模板
- 当前草稿导入预览结果
- 当前创建/编辑步骤
- 是否存在未保存变更
- 保存中状态
- 发布校验结果

新增 `ownerDashboardStore`，承载仪表盘状态：

- 仪表盘统计数据
- 最近任务摘要
- 仪表盘加载状态
- 仪表盘错误信息

状态边界：

- 服务层负责获取和提交数据，不直接保存 UI 状态。
- Store 负责跨页面共享、流程恢复和操作状态。
- 表单控件的临时输入、弹窗开关、表格当前页等短生命周期状态可以保留在组件内部。
- 发布校验结果需要进入 `ownerDraftStore`，供创建页、预览区和发布按钮共享。
- 导入预览结果需要进入 `ownerDraftStore`，避免发布校验和预览展示各自维护一份数据。

### 3. Owner 仪表盘

展示 Owner 当前工作概览：

- 总任务数
- 草稿任务数
- 已发布任务数
- 进行中任务数
- 当前重点任务进度
- 待处理导入异常数

仪表盘应提供进入任务管理和创建任务的入口。

### 4. 任务管理

实现 Owner 任务列表：

- 任务标题、状态、关联模板、数据量、更新时间、截止时间
- 当前进度，至少展示已完成量 / 总数据量和完成率
- 按关键词搜索
- 按状态筛选
- 状态标签展示
- 任务详情或编辑入口
- 草稿任务可发布
- 已发布任务可暂停
- 暂停任务可恢复
- 进行中或已发布任务可结束

状态操作必须有二次确认和结果反馈。

任务详情或当前任务区域需要展示进度明细：

- 总数据量
- 已分发量
- 已完成量
- 待审核量
- 通过量
- 驳回量
- 完成率
- 异常数量

### 5. 任务创建与编辑

支持创建和编辑任务草稿：

- 标题
- 描述
- 富文本说明可先降级为多行文本
- 标签
- 截止时间
- 奖励规则
- 分发策略
- 关联模板

保存后任务进入草稿状态。编辑页应能从已有草稿回填数据。

### 6. 数据集导入与预览

支持 Owner 在任务创建或编辑流程中配置数据集导入：

- 提供 JSON / JSONL / Excel 文件入口的 UI 占位。
- P0 可不解析真实文件，先使用 `src/mocks/` 中的数据集 Mock 数据模拟导入结果。
- 展示字段映射预览。
- 展示样本数据预览。
- 展示导入错误列表。
- 发布前必须能识别“无数据”或“导入存在阻断错误”的状态。

### 7. 发布校验

发布任务前执行前端校验：

- 必填基础信息完整。
- 已关联模板。
- 已存在可用导入数据。
- 导入结果无阻断错误。
- 当前任务状态允许发布。

校验失败时给出贴近操作的错误提示。

## P1：Owner 工作台体验增强

### 1. 仪表盘增强

- 增加最近任务列表。
- 增加异常数据快捷入口。
- 增加导出任务状态占位。
- 增加任务状态分布展示。

### 2. 任务管理增强

- 支持分页。
- 支持更多筛选条件，例如模板、截止时间、更新时间。
- 支持表格排序。
- 增加空态、加载态、错误态。
- 增加批量状态操作的 UI 预留，但不要求真实批量执行。

### 3. 创建流程增强

- 将任务创建拆分为步骤式流程：基础信息 -> 数据导入 -> 预览确认 -> 发布。
- 页面切换或刷新前提示未保存内容。
- 草稿保存后提供明确反馈。
- 富文本说明后续可替换为真正富文本编辑器。

### 4. 导入预览增强

- 支持字段映射手动调整的 UI 预留。
- 区分警告与阻断错误。
- 支持查看错误行详情。
- 为后续真实文件解析和后端导入任务预留状态字段。

### 5. Mock 数据增强

- `src/mocks/` 中继续按业务类型扩展 Mock 数据，避免单个 Mock 文件过大。
- 增加 Mock 数据索引文件，统一导出各类 Mock 数据。
- Mock 数据字段应尽量贴近领域类型，减少页面临时转换。
- 为异常、空数据、长列表等场景准备独立 Mock 样本。

### 6. 可维护性增强

- Owner 页面避免纯表单堆叠，使用“概览 + 主操作区 + 状态反馈”的工作台结构。
- 任务状态、状态文案、状态颜色集中维护。
- Mock 数据、服务方法与页面组件分离。

## 产出

- Owner 可以查看任务总览。
- Owner 可以创建并保存任务草稿。
- Owner 可以编辑任务基础信息。
- Owner 可以查看任务列表并筛选任务。
- Owner 可以查看当前任务进度和任务进度明细。
- Owner 可以查看导入数据预览与导入异常。
- Owner 可以完成任务发布前校验。
- Owner 可以切换任务状态，并获得确认和反馈。
- 项目具备阶段二业务 Mock 数据目录、分类型 Mock 文件和服务层基础结构。
- 项目具备 Owner 阶段业务 store，能够承载列表、详情、草稿、导入预览、发布校验和仪表盘状态。

## 验收标准

- 任务负责人可以完成“创建任务 -> 配置基础信息 -> 导入数据 -> 预览 -> 发布”。
- 任务列表搜索和状态筛选结果正确。
- 当前任务进度展示正确，完成率需要由已完成量和总数据量计算得出。
- 状态操作有二次确认、成功反馈和失败提示。
- 发布前缺少模板、缺少数据或存在阻断错误时必须阻止发布。
- 导入异常能展示具体原因。
- Mock 数据必须单独放在 `src/mocks/` 目录下，并按数据类型拆分文件。
- Owner 相关业务数据不直接硬编码在页面组件中。
- 任务列表、任务详情、任务进度、草稿、导入预览、发布校验和仪表盘数据必须有明确的 store 承载边界。
- 不允许同一份任务草稿或导入预览数据在多个组件中重复维护。
- 阶段二完成后运行 `npm run build` 和 `npm run lint`，并记录验证结果。

## 风险

- 阶段一尚未建立 `services` 和 API Client，阶段二需要先补 Mock 服务层，否则页面容易直接耦合静态数据。
- Mock 数据如果不分类型维护，后续任务、模板、导入、仪表盘数据会混杂，影响扩展。
- Owner 创建流程涉及草稿、导入预览和发布校验，如果缺少统一 store，页面之间容易出现状态不一致。
- 发布校验依赖模板与导入数据状态，P0 需要先定义清楚前端可判断的最小字段。
- 数据导入真实解析可能扩大范围，P0 默认只做 Mock 导入结果和预览 UI。
- Owner 页面容易变成表单堆叠，布局需要保持工作台信息结构。
