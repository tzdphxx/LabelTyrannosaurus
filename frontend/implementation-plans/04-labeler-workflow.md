# 阶段四：标注闭环

## 目标

让标注员完成从任务领取到作答、草稿、提交、查看打回并修改的完整闭环。

## 覆盖任务

- 任务 13：任务广场与领取
- 任务 14：标注工作台
- 任务 15：我的数据

## 实施阶段

### P0：标注员领域基础与 Mock 闭环

目标：先建立计划四需要的领域模型、Mock 数据、服务层和状态层，让后续页面都有统一数据来源。

实施内容：

- 新增标注员领域类型：
  - 任务广场任务摘要。
  - 标注任务详情。
  - 题目项。
  - 标注草稿。
  - 标注提交记录。
  - 审核意见摘要。
  - 我的数据统计。
- 新增标注员 Mock 数据：
  - 可领取任务。
  - 已领取任务。
  - 进行中任务。
  - 已提交任务。
  - 已通过任务。
  - 已打回任务。
  - 待修改任务。
  - 历史提交记录。
- 新增标注员服务层：
  - 查询任务广场列表。
  - 查询任务详情。
  - 领取任务。
  - 查询工作台题目列表。
  - 查询题目详情与 schema。
  - 查询草稿。
  - 保存草稿。
  - 提交答案。
  - 查询打回原因和审核意见。
  - 查询我的数据统计与提交列表。
- 新增 `labelingStore`：
  - 承载任务广场筛选条件。
  - 承载任务广场列表、加载态、错误态。
  - 承载当前工作台任务、题目列表、当前题目。
  - 承载草稿状态、保存状态、提交状态。
  - 承载我的数据统计和历史记录。
- 接入标注员导航项：
  - 任务广场。
  - 标注工作台入口。
  - 我的数据。
- 接入标注员路由：
  - `/app/labeler/market`
  - `/app/labeler/workbench/:taskId`
  - `/app/labeler/submissions`

验收标准：

- 标注员相关 Mock 数据可以被服务层读取。
- `labelingStore` 可以完成任务列表加载、任务详情加载、草稿读写和提交状态更新。
- 标注员导航可以进入计划四的三个核心页面。

### P1：任务广场与任务领取

目标：完成标注员领取任务的入口，让标注员可以从任务广场筛选任务并领取。

实施内容：

- 新增任务广场页面。
- 页面顶部提供任务搜索能力：
  - 按任务标题搜索。
  - 按任务描述搜索。
- 提供标签筛选：
  - 展示任务已有标签。
  - 支持按单个标签过滤。
  - 支持清空标签筛选。
- 提供状态筛选：
  - 全部。
  - 可领取。
  - 已领取。
  - 进行中。
  - 已结束。
- 提供任务展示视图：
  - P0 默认使用卡片视图。
  - 卡片展示标题、描述、标签、截止时间、题目数量、当前状态。
  - 卡片展示领取或继续标注入口。
- 实现任务领取：
  - 可领取任务点击后变为已领取或进行中。
  - 已领取任务点击后进入工作台。
  - 不可领取任务禁用领取按钮。
  - 领取成功后给出反馈。
- 任务领取后同步更新：
  - 任务广场列表状态。
  - 当前工作台可访问状态。
  - 我的数据中的进行中统计。

验收标准：

- 标注员可以在任务广场搜索、筛选任务。
- 标注员可以领取可领取任务。
- 领取后可以进入对应任务的工作台。
- 已领取任务不会重复领取。

### P2：标注工作台基础作答流程

目标：完成 schema 驱动的标注工作台，让标注员可以按题目作答、切题和手动保存。

实施内容：

- 新增标注工作台页面。
- 建立三栏布局：
  - 左侧题目导航区。
  - 中间 schema 表单作答区。
  - 右侧任务信息、保存状态和提交区。
- 左侧题目导航区支持：
  - 展示题目序号。
  - 展示题目作答状态。
  - 点击题目跳转。
  - 高亮当前题目。
- 中间作答区支持：
  - 使用动态表单 Renderer 渲染题目 schema。
  - 根据题目草稿回填初始值。
  - 根据历史答案回填可编辑初始值。
  - 展示表单加载态、空态和错误态。
- 右侧辅助区支持：
  - 展示任务标题。
  - 展示任务说明。
  - 展示当前题目进度。
  - 展示最近保存时间。
  - 展示保存中、已保存、保存失败状态。
- 支持题目导航操作：
  - 上一题。
  - 下一题。
  - 点击题号跳题。
- 支持手动保存草稿：
  - 保存当前题目答案。
  - 保存成功后更新题目状态。
  - 保存失败时保留当前输入内容。

验收标准：

- 标注员可以进入工作台看到题目列表。
- 标注员可以在中间区域完成 schema 表单作答。
- 标注员可以上一题、下一题和跳题。
- 标注员可以手动保存当前题草稿。

### P3：自动草稿保存与刷新恢复

目标：完成草稿自动保存和页面刷新恢复，确保工作台编辑内容不会因为刷新或切换丢失。

实施内容：

- 增加自动保存策略：
  - 表单值变化后延迟保存。
  - 频繁输入时合并保存请求。
  - 切题前触发当前题保存。
  - 离开工作台前尽量保存当前编辑值。
- 增加草稿持久化：
  - Mock 阶段通过服务层封装本地持久化。
  - 按用户、任务、题目维度保存草稿。
  - 页面不直接操作持久化实现。
- 增加草稿恢复：
  - 工作台初始化时读取当前任务草稿。
  - 切题时读取对应题目草稿。
  - 刷新页面后恢复最近编辑内容。
- 增加草稿状态提示：
  - 未保存。
  - 保存中。
  - 已保存。
  - 保存失败。
- 增加保存失败处理：
  - 展示失败提示。
  - 保留当前表单值。
  - 提供手动重试入口。

验收标准：

- 标注员输入后可以自动保存草稿。
- 页面刷新后可以恢复未提交草稿。
- 切换题目后再回来，之前的草稿仍然存在。
- 自动保存失败时不会清空用户输入。

### P4：提交校验与提交反馈

目标：完成正式提交动作，确保提交前能校验动态表单并给出明确反馈。

实施内容：

- 新增提交前检查：
  - 检查当前题是否满足 schema 校验。
  - 检查整份任务是否存在未完成题目。
  - 检查必填字段是否缺失。
- 表单校验失败时：
  - 定位到失败字段。
  - 展示字段错误信息。
  - 若字段在 Tab 或分组内，切换到对应区域。
- 提交动作支持：
  - 提交当前任务全部答案。
  - 提交前二次确认。
  - 提交中按钮防重复点击。
  - 提交成功后更新任务状态。
  - 提交失败后保留当前答案和草稿。
- 提交成功后：
  - 展示提交成功反馈。
  - 更新任务广场状态。
  - 更新我的数据统计。
  - 允许跳转到我的数据查看记录。
- 提交记录写入 Mock 数据：
  - 提交 ID。
  - 任务 ID。
  - 标注员 ID。
  - 提交时间。
  - 提交状态。
  - 结构化答案。

验收标准：

- 表单校验失败时不能提交。
- 校验失败可以定位到对应字段。
- 提交成功后任务状态变为已提交或待审核。
- 提交失败不会丢失草稿。

### P5：打回修改流程

目标：完成被打回任务的查看、回填、修改和重新提交。

实施内容：

- 扩展打回任务数据：
  - 打回原因。
  - 上一轮审核意见。
  - 上一轮提交答案。
  - 审核时间。
  - 审核员信息。
- 工作台识别打回任务：
  - 打回任务进入工作台时展示打回提示。
  - 右侧辅助区展示打回原因。
  - 右侧辅助区展示上一轮审核意见。
- 回填历史答案：
  - 使用上一轮提交答案作为当前可编辑初始值。
  - 保留上一轮提交记录作为只读历史。
  - 当前编辑答案独立保存为新草稿。
- 修改后重新提交：
  - 重新执行提交前校验。
  - 生成新的提交记录。
  - 更新任务状态为已提交或待审核。
  - 保留旧提交记录和审核意见。
- 我的数据联动：
  - 待修改任务可进入工作台。
  - 重新提交后从待修改移出。
  - 历史记录中展示多次提交。

验收标准：

- 打回任务可以看到打回原因。
- 打回任务可以看到上一轮审核意见。
- 打回任务可以回填历史答案并继续编辑。
- 修改后重新提交不会覆盖旧提交记录。

### P6：我的数据与提交历史

目标：完成标注员自己的数据看板和历史提交记录。

实施内容：

- 新增我的数据页面。
- 顶部展示统计卡片：
  - 已提交。
  - 已通过。
  - 已打回。
  - 待修改。
  - 进行中。
- 下方展示提交记录列表：
  - 任务标题。
  - 提交时间。
  - 当前状态。
  - 审核结果。
  - 审核意见摘要。
  - 操作入口。
- 支持列表筛选：
  - 全部。
  - 已提交。
  - 已通过。
  - 已打回。
  - 待修改。
- 支持列表搜索：
  - 按任务标题搜索。
  - 按任务描述搜索。
- 支持操作入口：
  - 待修改任务进入工作台。
  - 进行中任务继续标注。
  - 已提交任务查看提交详情。
  - 已通过任务查看只读结果。
- 提交详情支持：
  - 展示提交答案摘要。
  - 展示提交时间。
  - 展示审核结果。
  - 展示审核意见。

验收标准：

- 标注员可以看到自己的数据统计。
- 标注员可以筛选和搜索历史提交记录。
- 待修改任务可以从我的数据进入工作台。
- 历史提交记录状态与工作台提交结果一致。

### P7：收尾、验证与文档同步

目标：完成计划四收尾验证，确保主流程可演示、状态一致、文档同步。

实施内容：

- 校验主流程：
  - 登录标注员。
  - 进入任务广场。
  - 领取任务。
  - 进入工作台。
  - 作答。
  - 自动保存草稿。
  - 刷新恢复草稿。
  - 手动保存。
  - 提交。
  - 进入我的数据查看记录。
- 校验打回流程：
  - 从我的数据进入待修改任务。
  - 查看打回原因。
  - 回填历史答案。
  - 修改答案。
  - 重新提交。
- 校验页面状态：
  - 加载态。
  - 空态。
  - 错误态。
  - 保存中状态。
  - 提交中状态。
- 校验构建与静态检查：
  - 优先执行 `npm run build`。
  - 优先执行 `npm run lint`。
  - 如果当前环境仍无法找到 `node`、`npm` 或 `nvm`，在进度文档中记录未验证原因。
- 同步进度文档：
  - 更新 `memory-bank/progress.md`。
  - 记录已完成内容。
  - 记录当前约束。
  - 记录验证结果。

验收标准：

- 标注员主流程可以完整走通。
- 草稿刷新恢复可以演示。
- 打回修改可以重新提交。
- 我的数据统计与提交记录一致。
- 构建和 lint 有明确执行结果或未执行原因。
