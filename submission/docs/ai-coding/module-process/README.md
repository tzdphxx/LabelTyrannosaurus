# 模块级开发过程索引

本目录记录各模块在开发过程中如何使用 AI 辅助进行计划、执行、review 和测试。内容围绕业务主线展开：任务创建、动态模板、标注提交、AI 预审、人工终审、审核通过后导出。

Owner 侧重点在任务发布契约，包括基础信息、模板版本、数据导入、AI 审核配置和发布校验。AI 在这一部分主要用于拆解发布前置条件，避免任务只完成页面录入却无法进入标注流程。

Labeler 侧重点在领取、草稿和提交。AI 帮助把动态表单作答拆成前端交互、服务端草稿、模板版本校验和重复提交控制，确保灵活作答不会削弱结果可信度。

AI 审核侧重点在 Provider、模型输入、多模态降级、异步队列和策略流转。AI 在这里既参与方案设计，也用于反向审查模型失败、低置信度和风险命中后的兜底路径。

Reviewer 侧重点在人工终审、任务级领取、通过/打回、修订版本和权限边界。AI 的作用是提前暴露并发审核、越权读取和历史覆盖风险，让人工终审成为可追溯的安全边界。

平台支撑侧重点在 Provider 管理、导出、审计和可观测性。Provider 保证模型能力可控，导出保证只输出审核通过的数据，可观测记录保证 AI 参与过程可解释。

质量 review 和测试侧重点在安全、性能、异步可靠性和集成验证。AI 用于系统性梳理状态条件更新、N+1 查询、队列重放、权限一致性和端到端闭环验证。
